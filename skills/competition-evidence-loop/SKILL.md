# 竞赛证据闭环

把单次任务的成功或失败转化为可复验的方法。Agent 负责证据整理、问题定位和候选提议；确定性工具负责读写、训练、评价和发布。角色数量不证明收益，独立评价不能由候选规划者自行改写。

按当前任务选择下面需要的模式，不要强迫所有模式每次串行执行。每个模式的交接至少记录：任务/输入版本、允许操作、已确认事实、未知项、输出工件、检查结果、状态与失败原因。`passed` 仅表示该模式的合同通过，不等于模型达标、平台接收或生产发布。

## 1. 规则与提交合同

新赛事、规则变化或提交前，读取官方说明、样例、真实解析器和输出模板。形成版本化的任务目标、合法资源与字面提交合同；用最小合法例子验证字段、编码、空值、文件名和包限制。规则或权限不明时保留疑问，不宣称可正式提交。

## 2. 原始资料语义

新资料包先登记来源、许可、原件关系和标注层。逐字原文、音标、译文、释义及意图分别保存。工具确定的唯一关系保持锁定；模型只提议未知项。映射歧义、标签语义或说话人不明时进入审核，而不是从文件名推断。文字映射通过也不自动获得训练和评价资格。

## 3. 基线与运行保护

试验前或中断续接时，检查基线模型、数据索引、配置、依赖、报告、任务终态及禁止重跑清单。记录校验值和版本谱系；必要时做最小回载。新试验用独立输出，不能覆盖无法确认的历史文件或重复启动仍在运行的任务。

## 4. 有界变更

出现可复现问题时，先核评价、输入和资料，再定位可能的流程或模型根因。每轮登记一个最小变更对象、预期机制、主指标、预算、停止与回退条件。耦合改动需预设消融。执行轨迹保留初次失败；候选获准研究不等于自动获准训练或部署。

## 5. 独立评价

候选执行后，使用冻结的参考、分组和指标复算主效果、纠错、回退、完整性、历史回归及资源消耗。检查说话人、原录音、派生版本和资料来源重叠。若声称多 Agent 有价值，与固定工具流程和单决策 Agent 在相同证据、工具、模型候选及预算下对照；保留负结果。小样本或开发集不能充当泛化证明。

## 6. 交付与经验沉淀

从接收者入口复验压缩包、模型回载、接口、页面与媒体等实际工件。公开材料区分已实现、已运行、已验证和目标设计。记录通过、失败、未验项、适用范围及回退入口；上传成功不等于平台评分通过，演示成功不等于临床有效或任意语言达标。

## 采用条件

只有预设质量、非退化、完整性和必要非功能门同时通过，才建议采用候选。证据不足或无净收益时保留基线并记录拒绝原因。任何新的外传、资金、资料许可、正式提交或生产发布仍须在当次任务中取得明确授权。
